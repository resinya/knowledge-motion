# 风格、场景与节奏

## 视觉语言

参考 [Git 命令](https://www.douyin.com/video/7691634216315931919)、[端口速查](https://www.douyin.com/video/7697497434749963555) 与 [URL 请求](https://www.douyin.com/video/7695387064098966811) 的深色分区、局部过程动画与逐步聚焦；这些是视觉观察，不代表对原作者软件的判断。

背景近黑深蓝，内容区稍亮，以细描边分层。白色主文字、灰蓝注释、青蓝焦点、青绿完成状态；紫、绿、橙可区分对象或分类。对象颜色和名称跨镜头保持一致，图标、路径和文字统一使用 SVG。

总览展示大模块与关系；进入机制后，主要空间给当前过程，保留当前位置导航。无需一直把全部细节挤在同一张六宫格。回到总览时保留已完成结果，说明本模块给下一模块带来了什么。

## 画幅与密度

用户指定的平台和尺寸优先；未指定时按最关键关系选择，全片统一：

| 关键关系 | 优先考虑 |
| --- | --- |
| 双端时序、树的合并、并排对照、代码与结构联动 | 1920×1080 横屏 |
| 单向连续过程、分类速查、手机观看 | 1080×1920 竖屏 |

每个镜头突出一个主要变化，复杂机制拆成多个镜头或动作阶段。主要标签应能在实际观看尺寸下读清；1080 像素短边通常使用约 30–36 px 标签、24–28 px 辅助文字、52–64 px 标题，按镜头布局调整。过密时重排、换行或拆镜，不能一味缩小文字。中文长词、英文术语和边缘留白都要看实际帧。

## 场景选择

| 场景 | 适合表达 | 动作重点 |
| --- | --- | --- |
| overview | 知识全貌、章节入口与回顾 | 当前模块、已完成模块、下一步输入 |
| sequence | 双端或多方交互 | 每次传递的方向、内容和收发状态 |
| tree | DOM 等结构增长、树合并 | 节点何时出现、父子关系和合并依据 |
| parallel | 同时处理、依赖与汇合 | 各路起点、独立进度、汇合条件 |
| branch | 条件选择 | 判断依据、所选路径、未选条件 |
| state | 指标或状态变化 | 操作前后及数值原因，结果连续 |
| linked | 代码、结构与结果联动 | 同一个输入在不同表示中的对应位置 |
| list | 分类与速查 | 类别色稳定，逐项强调关键差异 |
| custom | 基础场景不能准确表达的机制 | 在生成项目实现 SVG／React，沿用局部帧与画幅 |

场景名称和字段以 [数据契约](story-contract.md) 为准。不要把所有主题都改写成“图标 → 图标 → 图标”，也不要为了展示所有基础场景而扭曲知识。

## 动作语义

| 动作 | 表现 | 意义 |
| --- | --- | --- |
| 聚焦 | 描边、亮度提升 | 现在看哪里 |
| 路径展开 | 连线从起点展开 | 关系建立方向 |
| 对象移动 | 文件、报文或标签沿路径移动 | 谁向谁传递什么 |
| 逐步输入 | 短输入、代码、数值依次出现 | 操作正在发生 |
| 状态变化 | 节点增长、颜色／状态／数值切换 | 动作产生的结果 |
| 结果停留 | 变化结束后保留 | 为理解和下一镜头留下基础 |

先焦点、再动作、再结果只是编排起点。时序交互要逐次展示消息抵达和状态变化；并行不能被动画错误地串行；条件路径要说明触发条件。语义结果与相邻镜头衔接，不添加无意义的漂浮、粒子或大幅转场。

## 内容决定时间

没有统一的 20 秒默认值或 120 秒上限。分别估算每镜头的阅读时间、动作演示时间、结果停留时间，再求整片长度。新概念较多的镜头需要更久；熟悉的结构回顾可以短些，不能按镜头数平均分配。

有明确短时长要求时先缩小解释范围，并说明取舍，不能将必要机制快放到看不懂。默认交付一条带章节的完整视频；不额外生成多个画幅。

## 视觉验收

查看章节入口、关键动作前后、机制完成和镜头交接。暂停时对象与关系能被理解，播放时能跟上变化；核对中文字体、连线端点、状态连续与对象身份。最终实际播放；媒体报告只证明规格，不能代替画面与知识验收。
